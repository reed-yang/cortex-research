# Product 0.1.25

Status: deployed; installed-adapter and live Capture acceptance passed.

This release fixes a repeated paper capture failing with `invalid_source` after
the ingestion engine has successfully found an already indexed paper. The
second capture produced the same adoption manifest under a new command key;
the engine adapter misclassified Control's `already_adopted` refusal.

The adapter now reuses the identical immutable manifest only within the same
corpus root, after verifying the current canonical source, engine reference and
ready import state. Distinct captures can finish consumed with the same source
without adding another paper directory. Bulk adoption keeps its existing
idempotency rules; other identity conflicts remain failures.

Validation: 67 engine-port, capture-consumer and Control-adoption tests passed.
Regression tests reproduce the previous failure for separate captures and a
prior operator adoption, and cover foreign roots, stale bindings and other
conflict refusals. A clean installed 0.1.24 engine ingestion had already passed
real download and embedding checks; the defect was in subsequent adoption.

The Control schema remains 19 and the selected worker remains
`hermes-0.15.0-gen10`; this patch changes no worker payload. Installation and
live Capture acceptance were measured separately from source tests. The verified
bundle passed isolated installation and lifecycle checks. Its installed adapter
consumed two separate captures following operator adoption; the upgraded live
daemon then consumed the original incident payload through its normal scheduler.
The workflow effect completed, the existing source was reused, and the original
paper files were unchanged. Worker identity and native sessions were preserved.

Earlier failed captures remain historical attempts; retry through a new capture
after the patch is installed. These checks did not send Telegram messages.
