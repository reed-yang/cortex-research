# Product 0.1.27

Status: candidate.

An arXiv paper without a LaTeXML HTML version can now be ingested through an
OCR skill the operator installs and accepts. Previously every such Capture
failed as `materialization_failed` within seconds, because the engine's OCR
path was unreachable by design. The bundle still ships no OCR.

`[skills] root` names where operator skills live. A skill declares the `ocr`
capability, its entry and its prepared interpreter in the Agent Skills
`metadata` map. `cortex skills accept` records a digest of the package. Every
engine effect recomputes it and binds the skill into the child only while it
matches, so a skill changed by an edit, a pull or a sync tool stops running
until it is accepted again. The engine runs the declared interpreter directly
and never uv. The skill receives the OCR credentials but not the embedding
credential. The OCR budget is now 420 seconds, inside the 600-second child
timeout.

A PDF-only paper that cannot be OCRed here fails as `capability_unavailable`,
distinct from `materialization_failed`. The inbox card says OCR is not ready;
`cortex skills status` and `cortex doctor` name the reason. See
[operator skills](../runbooks/operator-skills.md) and
[ADR 0011](../adr/0011-operator-skill-capabilities.md).

The Control schema remains 19; worker `hermes-0.15.0-gen10` is unchanged.
Configuration gains an optional `[skills]` section, which 0.1.26 ignores.
