# Product 0.1.27

Status: deployed; isolated lifecycle, installed OCR and live upgrade checks passed.

An arXiv paper without a LaTeXML HTML version can now be ingested through an
OCR skill the operator installs and accepts. Previously every such Capture
failed as `materialization_failed` within seconds, because the engine's OCR
path was unreachable by design. The bundle still ships no OCR.

`[skills] root` names where operator skills live. A skill declares the `ocr`
capability, its entry and its prepared interpreter in the Agent Skills
`metadata` map. `cortex skills accept` records a digest of the package. Every
engine effect recomputes it and binds the skill into the child only while it
matches, so a skill changed by an edit, a pull or a sync tool stops running
until it is accepted again. The engine runs the declared interpreter directly
and never uv. The skill receives the OCR credentials but not the embedding
credential. The OCR budget is now 420 seconds, inside the 600-second child
timeout.

A PDF-only paper that cannot be OCRed here fails as `capability_unavailable`,
distinct from `materialization_failed`. The inbox card says OCR is not ready;
`cortex skills status` and `cortex doctor` name the reason. See
[operator skills](../runbooks/operator-skills.md) and
[ADR 0011](../adr/0011-operator-skill-capabilities.md).

The Control schema remains 19; worker `hermes-0.15.0-gen10` is unchanged.
Configuration gains an optional `[skills]` section, which 0.1.26 ignores.

The candidate bundle passed both verifiers and isolated install/start/status/
doctor/stop checks. Its installed interpreter then ran a real Capture effect for
the PDF-only paper 2609.07398 against empty disposable roots, with the
operator's skill accepted there: OCR produced a 145,581-character body, 24 of 24
figures and 59 indexed chunks, the write boundary held, no process survived and
the skill's digest was unchanged afterwards. The checker's last assertions ran
from the saved execution record after a checker defect, without a second OCR
request.

Production was archived while stopped. Its last backup proof was older than
the seven-day window, so a fresh verified proof was recorded before the
supported upgrade. `[skills]` was then configured and the skill accepted with
the installed 0.1.27 code; dispatch and Telegram activation were restored.
Doctor reports `skills: ocr ready`, the Web build is healthy, the gen10 worker
launched, and all seven runtime bindings, eight native sessions and 56 messages
were preserved. No PDF-only Capture has yet run through the live daemon.

Validation: 3,069 tests passed outside `tests/distribution`; the one failure is
the citation lint, which also fails on the predecessor source. Distribution
tests passed except one that copies the development interpreter with `venv`,
which cannot start on the build host. Web fast checks passed 418 tests.
