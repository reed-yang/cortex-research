# Product 0.1.28

Status: selected; build, isolated acceptance and production upgrade pending.

This release collects the Inbox, Capture, research-evidence and readings changes
merged since 0.1.27 (#22, #29-#41) and raises the Control schema from 19 to 20.

**Idea fragments.** The Web Inbox has an idea composer and Telegram accepts
`/idea <text>`. Each saves the text verbatim as a fragment and does nothing
else: no model turn, no capture, no research item. Control migration 20 adds the
append-only `idea_fragments` table. Telegram splits a message longer than 4,096
characters; only the first part carries `/idea`, and the following parts
arrive as ordinary messages.

**Capture.** A Capture payload may name exactly one arXiv paper anywhere in its
text, as a bare modern ID, `arXiv:<id>`, or an `arxiv.org` abs, pdf or html URL.
The text around it is kept as the payload note. Two different papers are
refused. A failed Capture whose paper is already adopted links to that source.

**Inbox.** Captures are listed newest first and are reread while the Inbox is
open. The Inbox fits a 390-pixel phone without sideways scrolling, and its
buttons meet the 44-pixel touch floor there.

**Research evidence.** Answers read the v2 citation group grammar
(`[S1, S2]`, `[S1][D2]`) and stay DRAFT when a label is malformed. Retrieval
uses a derived query: the selected item's title is prepended, and citation
labels, length requirements and format words are removed, with a fallback to
the raw text. Each source contributes up to two indexed passages, dossier
excerpts are ranked by distinct query terms, and evidence windows include a
paper's own Limitations or Conclusion section and its notes' Key Results and
Limitations.

**Readings.** The publisher's `verify_no_delete` self-check now passes the
queried path to the variadic `sandbox_check`. On arm64 under CPython 3.14 the
previous call passed in an unsandboxed process, so in 0.1.27 the self-check
did not check anything. The sandbox profile itself was applied in both versions.

Checkout tools gained a read-only corpus asset-reference audit and a
checkpointed retrieval evaluation harness; neither runs in the installed
product.

Control schema 20 is reached from 16, 17, 18 or 19. The worker
`hermes-0.15.0-gen10` is unchanged. `state_archive.py` accepts schema 20, so a
19 -> 20 upgrade has a baseline archive and a recovery script like earlier
schema pairs.
